# Web3nity Students Platform — Design

**Дата**: 2026-05-08
**Клиент**: Hannah Web3nity (курс "AI-Ассистенты 3.0", сайт ai-education.io)
**Контакты по проекту**: Инна, Андрей (детализация требований)
**Назначение**: публичная витрина студентов курса (профили + работы) для нетворкинга и демонстрации кейсов; данные собираются из закрытого Telegram-чата курса.

---

## 1. Цели и контекст

**Что строим**
1. Публичная страница "Студенты" в стиле ai-education.io — встраивается в существующий сайт клиента.
2. Telegram-бот — личный кабинет студента: редактирование профиля, загрузка работ.
3. Пайплайн сбора данных из закрытого Telegram-чата "AI-АССИСТЕНТЫ 3.0": разовый импорт из HTML-выгрузки + постоянный pull через бота, добавленного в чат админом.

**Что узнали из выгрузки** (`/Users/lvmn/Downloads/Telegram Desktop/ChatExport_2026-05-08`)
- 2030 сообщений, 108 авторов (~100 студентов + кураторы).
- Курс стартовал 2026-04-20, выгрузка от 2026-05-08 (2.5 недели курса).
- ~150 длинных самопрезентаций со стабильным паттерном: имя, возраст, город, ниша, цель обучения, экспертиза, хобби. 33 поста с явным `#обомне`, остальные без хештега.
- Только 20 студенческих сообщений с медиа, и большинство — рабочие скрины из Q&A веток, не готовые кейсы. **Ветка "Дневник побед" фактически пуста — кейсы появятся к концу курса.**

**Следствия для дизайна**
- На старте ценность сайта = нетворкинг (карта людей, фильтры). Работы наполнятся через 1–2 месяца.
- Архитектура поддерживает работы, но MVP UX расставляет акценты на профилях.

**Видимость**: всё публично (профили + работы видны в открытом интернете).

## 2. Архитектура

Один монорепо `web3nity-students/`, четыре единицы:

```
web3nity-students/
  apps/
    bot/        Telegraf.js бот (Railway, long-polling)
    web/        Next.js 15 App Router (Vercel или их хостинг, SSG/ISR)
  packages/
    db/         Supabase клиент, миграции, типы
    parser/     Парсер HTML-экспорта + LLM-нормализация (Claude Haiku)
  scripts/
    import.ts   one-shot: HTML → DB
```

**Принципы разделения**
- `bot` и `web` независимы: один может падать или обновляться, другой работает.
- `parser` отдельным пакетом — переиспользуется в `import.ts` и в `bot` при pull-е.
- `db` пакет — единая правда о схеме и типах для обоих приложений.

**Внешние зависимости**
- Supabase (отдельный новый проект под клиента, не в общем).
- Telegram Bot — новый, регаем в @BotFather, добавляем админом в чат "AI-АССИСТЕНТЫ 3.0" с правом чтения сообщений.
- Anthropic API (Claude Haiku) для классификации сообщений и извлечения полей профиля.

**Деплой**
- Бот: Railway.
- Сайт: Vercel или хостинг клиента (уточняется при встраивании).
- Supabase: облако.

## 3. Модель данных

```sql
students
  id                 uuid pk
  telegram_user_id   bigint unique not null
  telegram_username  text
  display_name       text not null
  avatar_url         text
  city               text
  country            text
  niche              text                 -- "n8n-разработчик", "ВЭД-логистика"
  bio                text
  goal               text
  expertise          text
  hobbies            text
  age                int
  status             text                 -- 'looking_for_clients' | 'looking_for_partners' | 'just_learning' | null
  is_published       bool default true
  cohort             text                 -- "AI-Ассистенты 3.0"
  source_message_id  text                 -- ссылка на оригинальный intro
  created_at, updated_at

works
  id                 uuid pk
  student_id         uuid fk students
  title              text not null
  description        text
  media              jsonb                -- [{type:'image'|'video'|'pdf'|'link', url, caption}]
  tags               text[]
  source_message_id  text
  posted_at          timestamptz
  is_published       bool default false   -- для импорта по умолчанию false; через бот студент публикует сам
  created_at, updated_at

raw_messages
  id                 text pk              -- telegram message_id
  thread_id          bigint               -- topic id (только из bot pull)
  author_tg_id       bigint
  author_name        text
  text               text
  media              jsonb
  posted_at          timestamptz
  classified_as      text                 -- 'intro'|'work'|'qa'|'chat'|null
  processed_at       timestamptz
  ingested_from      text                 -- 'html_export' | 'bot_pull'

tags
  slug               text pk
  label              text
  type               text                 -- 'niche' | 'skill' | 'work_category'

bot_sessions
  telegram_user_id   bigint pk
  state              text
  context            jsonb
  updated_at
```

**Storage**
- `students-avatars/<student_id>.png`
- `works-media/<student_id>/<work_id>/<filename>`

**RLS**
- Анонимное чтение всех таблиц (витрина публичная).
- Запись только service_role (бот и скрипты).

**Решения**
- `cohort` поле — на будущее, чтобы новые потоки не смешивались.
- `raw_messages` отдельно — позволит переклассифицировать LLM-ом без повторного парсинга HTML.
- `media` как `jsonb` — гибкость, индексировать не нужно (на работу 1–3 файла).
- `works.is_published` для импортированных работ = `false` — сначала студент явно подтверждает публикацию через бота. Это снимает риск утечки чувствительных скринов из Q&A.
- `students.is_published = true` по умолчанию (профили не содержат конфиденциального).

## 4. Поток данных

### A. Разовый импорт (`scripts/import.ts`)

```
ChatExport_*/messages*.html
  ↓ packages/parser: парсит HTML, склеивает joined-сообщения, тянет медиа из ./files
  ↓ INSERT в raw_messages (всё подряд, classified_as=null)
  ↓ для каждого автора собираем длинные посты (>80 симв)
  ↓ Claude Haiku batched по 20 постов:
      - классифицирует: intro / work / qa / chat
      - для intro извлекает {name, city, country, niche, bio, goal, expertise, hobbies, age}
      - для work извлекает {title, description, tags}
  ↓ создаём student per author (берём наиболее полный intro)
  ↓ создаём work per work-сообщение, медиа копируем в Supabase Storage
  ↓ помечаем raw_messages.processed_at
```

Идемпотентность: повторный запуск с той же выгрузкой → UPSERT по `telegram_user_id` и `source_message_id`. Поля, отредактированные студентом через бот (определяем по `updated_at > intro.posted_at`), не перезаписываются.

Перед боевым запуском: режим `--dry-run` печатает план изменений без записи.

### B. Постоянный pull через бота

```
Бот в чате "AI-АССИСТЕНТЫ 3.0" как админ, Privacy Mode выключен
  ↓ on('message') в любом топике
  ↓ INSERT в raw_messages (с message_thread_id из update.message.message_thread_id)
  ↓ если автор есть в students — обновляем last_seen
  ↓ если сообщение длинное (>100 симв) и автор без профиля:
      → ему в личку: "Заметил твой пост в нетворкинге. Создать профиль на витрине? /yes /no"
      → при /yes — Claude Haiku извлекает поля → student.is_published = true
```

Бот **не переписывает существующий профиль автоматически.** Любое обновление — через `/edit` команду студента.

### C. UX бота — личный кабинет

```
/start       приветствие, ссылка на свой профиль на сайте, краткая инструкция
/profile     показать свой профиль (как видят на сайте)
/edit        меню: имя, город, страна, ниша, био, цель, экспертиза, хобби, возраст, статус
/work_add    мастер: заголовок → описание → медиа → теги → опубликовать
/works       список своих работ → выбрать → редактировать / удалить / скрыть
/hide        снять профиль с витрины (is_published=false)
/show        вернуть на витрину
/forget      hard-delete профиля и работ (GDPR-friendly)
/help
```

FSM-состояние редактирования живёт в `bot_sessions`. После каждого действия бот шлёт ссылку на свой профиль на сайте.

При первом контакте бот показывает короткое согласие: "Твой профиль публикуется в открытом интернете. Контакты — только @username, который ты выберешь сам. /agree /no_thanks".

### D. Поток медиа

- Файлы из бота: скачиваем по `file_id` через Telegram Bot API → грузим в Supabase Storage → пишем URL в `works.media`.
- Лимит Bot API на скачивание — 20 MB. Для крупных видео бот предлагает прислать ссылку (YouTube, Drive, etc.) — храним как `{type:'link', url}`.
- Файлы из HTML-выгрузки: копируем из `./files` локального экспорта в Storage, прежний путь не сохраняем.

### E. Ошибки и крайние случаи

| Случай | Поведение |
|--------|-----------|
| Студент удаляет сообщение в чате | `raw_messages` остаётся (аудит), профиль/работа не меняются |
| LLM возвращает мусор | `raw_messages.processed_at=null`, retry-скрипт повторит |
| Студент без `username` | Показываем "Имя из Telegram", контакт скрываем; бот предлагает добавить @nick |
| Бот падает | Long polling сохраняет offset в Telegram, при возврате получит пропущенные апдейты |
| Студент в боте: "удалите меня" | `/forget` — hard-delete по `telegram_user_id` |
| Выгрузка содержит чувствительный скрин в "работе" | Импортированные `works.is_published=false`, публикация только через бот после явного действия студента |

## 5. Сайт-витрина

### Структура страниц

```
/students                       — список со фильтрами
/students/[slug]                — карточка студента + его работы
/students/[slug]/works/[id]     — отдельная работа
```

`slug` = `telegram_username` или транслит имени (если username нет; коллизии разрешаем суффиксом `-2`).

### Фильтры на списке
- Страна (multi-select)
- Ниша (из словаря `tags.type='niche'`)
- Статус (`ищу клиентов / партнёров / просто учусь`)
- Поиск по имени, нише, био

Сортировка по умолчанию — недавно обновлённые.

### Стиль (под ai-education.io)

- Палитра: чёрный `#0F0F0F`, кремовый `#F5EFE5`, оранжевый акцент `#E94E1B`, серая обводка.
- Заголовки: bold sans-serif uppercase. Тело: Inter / Manrope (или то, что уже подключено на ai-education.io).
- Карточки: квадратные, аватар сверху, имя крупно, под ним ниша + флаг страны, далее короткая строка из bio.
- Без теней, без градиентов, скругления ≤8px. Чёрные обводки 1–2 px вместо теней.
- Пустое состояние работ: "Скоро тут появятся кейсы. Студент только начал курс."

### Технические детали
- Next.js 15 App Router, ISR `revalidate=60` — обновления из бота подтягиваются за минуту.
- JSON-LD `Person` schema на странице студента (SEO для нетворкинга вовне).
- OG-картинки on-the-fly через `next/og` (имя + ниша + аватар на чёрном фоне).
- Без аналитики на старте; добавим Plausible или PostHog после согласования с клиентом.

## 6. Тестирование

- `parser/`: юнит-тесты на парсинг HTML (фикстура из 50 реальных сообщений), склейку joined, извлечение медиа.
- `parser/llm-extract`: снапшот-тесты на 10 реальных `#обомне` постов — проверяем формат и обязательные поля.
- `bot/`: интеграционные тесты на FSM (мок Telegram API), флоу `/edit`, `/work_add`, `/forget`.
- `web/`: E2E через Playwright — главная грузится, фильтры работают, карточка открывается, OG-картинка генерируется.
- Импорт-скрипт прогоняем на проде против реальной выгрузки в режиме `--dry-run` перед боевым запуском.
- Ручной аудит: после первого прогона LLM-классификации просматриваем 50 случайных семплов, корректируем промпт при необходимости.

## 7. Риски и митигации

| Риск | Митигация |
|------|-----------|
| Hannah не дала добавить нашего бота админом | Договариваемся заранее, минимум прав — только чтение сообщений |
| LLM путает intro / work / qa | Логируем все классификации; ручной аудит 50 семплов после первого прогона; правим промпт |
| Студенты не идут в бота редактировать профиль | Профили предзаполнены LLM-ом; Hannah делает анонс в чате со ссылкой на бота |
| Утечка чувствительных данных в работах из Q&A | `works.is_published=false` по умолчанию; публикация только через бот |
| Юридика: персданные в открытом доступе | Кнопка `/forget` (hard-delete); явное согласие при первом контакте бота; opt-in для работ |
| Витрина пустая в первый месяц курса | Дизайн рассчитан на это: упор на людей, работы — приятный бонус |

## 8. Скоуп MVP

**Входит**
- Скрипт импорта HTML-выгрузки.
- Бот: `/start /profile /edit /work_add /works /hide /show /forget /help`.
- Сайт: список студентов, страница студента, страница работы, фильтры, JSON-LD, OG.
- Деплой: Supabase (новый проект) + Railway (бот) + Vercel или передача статики клиенту.

**Не входит** (отложено)
- Поиск работ по тегам (только профили на старте).
- Нотификации (новый студент, новая работа).
- Админка для куратора — пока через Supabase Studio.
- Многоязычность UI (RU only на старте; сайт клиента имеет RU/EN/UA — добавим если попросят).
- Лиды / форма "написать студенту" — только кнопка "связаться в Telegram".
